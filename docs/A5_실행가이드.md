# A5 유찰 이후 후속공고·추가 소요일 분석 — 팀 공유용 실행 가이드

## 1. 목적과 사용 범위
이 스크립트는 새 공고의 유찰 *예측*이 아니라, 이미 유찰된 공고가 어떤 후속 공고로 이어졌는지와 후속 재공고 개찰까지의 관측 간격을 분석한다. **이후 발생한 정보는 사전 위험도 산정에 사용하면 안 된다.**

근거: 데이터 항목정의서(3.1~3.4, 4.2~4.3, 5.1~5.2), 프로젝트 정의서, KPI 정의서.

## 2. 입력 데이터
`data/clean/`에서 아래 접두사로 시작하는 CSV를 각각 **정확히 하나**씩 찾는다.
- `bid_notice_clean_*.csv`: 개별 공고 정보 (noticeKey, businessKey, pblancDate, opengDt, pblancSe 등)
- `bid_result_clean_*.csv`: 품목별 결과 (noticeKey, bidResult)

조달계획·계약정보 파일은 현재 A5 기본 집계에는 필요하지 않다.

## 4. 핵심 로직
1. `noticeKey` 단위로 결과를 묶고, 유찰+비유찰 혼재를 `판단보류`로 보존한다.
2. 공고일이 2021-01-01~2025-12-31인 **유찰 공고**를 추적 대상으로 정한다.
3. 동일 `businessKey`의 유효 공고를 **개찰일순**으로 정렬하고, 개찰일이 뒤인 직후 공고를 연결 후보로 삼는다.
4. 후속 공고의 `pblancSe`로 재공고인지 판단하고, 후속 결과확정 여부도 별도로 판단한다.
5. 날짜 간격은 *후속 개찰일 - 직전 유찰 개찰일* (달력 일수)로 계산한다.
6. 마지막 분기 제외, 90일 완전 관측 가능 표본을 나란히 비교한다.

**주의:** 원문 A5 요구의 '후속공고+유효 날짜'와 프로젝트 정의서의 '결과확정 후속 재공고'는 서로 다른 기간 계산 모집단이다. 따라서 둘 다 별도 저장한다. 동일 개찰시각, 취소공고 제외 등 일부 연결 규칙은 문서에 충분히 확정되지 않아 코드에 구현 선택으로 명시했다.

## 6. 반드시 구분할 분모
- **후속공고 확인 비율**: 후속공고 연결 건수 / 추적 대상 전체 유찰공고 건수.
- **A5 원문 소요일**: 연결된 후속공고 중 개찰일 간격이 유효한 건.
- **프로젝트 정의서 추가 소요일**: 결과가 확정된 후속 *재공고* 중 간격이 유효한 건.

다른 모집단끼리 평균·건수를 섞지 않는다. 두 지표 모두 조달 전체 지연을 뜻하지 않는다.

## 7. 실행 테스트 결과 및 미해결 사항
현재 첨부 CLEAN 파일로 확인한 값: 분석기간 유찰 9,836건, 후속공고 연결 3,658건, 결과확정 후속 재공고 유효 소요일 2,996건, 평균 14.12일·중앙값 10일·Q1 7일·Q3 18일. 마지막 분기 제외 표본은 2025년 4분기(원공고일) 제외.

문서 기준은 유찰 9,845건, 후속공고 3,663건, 결과확정 후속 재공고 3,002건이다. 유찰 9건 차이는 공고일이 2020년인 자료의 기간 제외로 설명되지만, 나머지 연결 건수 차이는 확인·합의가 필요하다. `a5_validation_report.csv`의 불일치 항목을 해결한 뒤 공식 수치로 확정한다.
